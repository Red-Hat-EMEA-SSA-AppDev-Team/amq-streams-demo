= Console deployment

**Kafka Console** was introduced in _Streams for Apache Kafka version 2.8_ and became general available in _version 2.9_.

In this module you will learn how to install and configure the **Kafka Console** with no security enabled.

== Installation

Via _OperatorHub_, install the operator `Streams for Apache Kafka Console`.

Make sure to select Manual update.

Fish shell users can set the environment variables with the following commands:

[source,shell]
----
set -x KAFKA_NAMESPACE (oc project -q)
set -x CLUSTER_DOMAIN (oc get ingress.config.openshift.io/cluster -o jsonpath='{.spec.domain}')
----

Bash shell users can set the environment variables with the following commands:

[source,shell]
----
export KAFKA_NAMESPACE=$(oc project -q)
export CLUSTER_DOMAIN=$(oc get ingress.config.openshift.io/cluster -o jsonpath='{.spec.domain}')
----

Create a namespace for the console:

[source,shell]
----
oc new-project kafka-ui
----

== Connect to Kafka cluster with no security enabled

Finally, create the console resource:

[source,shell]
----
cat k8s/console/console.yaml | envsubst | oc apply -f -
----

Open it in the browser at the following URL: `kafka-console.${CLUSTER_DOMAIN}`

== Connect to a SCRAM-protected Kafka cluster

When Kafka uses `scram-sha-512` authentication and simple authorization, the Console needs its own `KafkaUser` and ACLs. First configure SCRAM authentication on every Kafka listener and simple authorization as described in xref:access.adoc#_authorization[Authorization].

The Console user needs cluster metadata permissions, access to topic metadata and records, and access to consumer group metadata. Create the supplied user in the namespace containing the Kafka cluster:

[source,shell]
----
oc -n "$KAFKA_NAMESPACE" apply -f k8s/console/console-user.yaml
----

`console-user.yaml` creates `console-kafka-user1` with the following minimum ACLs:

- Cluster: `Describe`, `DescribeConfigs`
- All topics: `Read`, `Describe`, `DescribeConfigs`
- All consumer groups: `Read`, `Describe`

The User Operator creates the `console-kafka-user1` credentials Secret in `$KAFKA_NAMESPACE`, whereas the Console resource and its service account run in `kafka-ui`. Grant that service account permission to read only this Secret:

[source,shell]
----
oc -n "$KAFKA_NAMESPACE" create role console-kafkauser-secret-reader \
  --verb=get \
  --resource=secrets \
  --resource-name=console-kafka-user1

oc -n "$KAFKA_NAMESPACE" create rolebinding console-kafkauser-secret-reader \
  --role=console-kafkauser-secret-reader \
  --serviceaccount=kafka-ui:kafka-ui-console-serviceaccount
----

If you deploy the Console with a different namespace or Console resource name, replace `kafka-ui:kafka-ui-console-serviceaccount` with its actual `namespace:serviceaccount` value. You can find the required service account in the Console `AccessDenied` message.

Deploy the SCRAM-aware Console resource. It selects the `plain` listener configured with SCRAM and references the `KafkaUser`; the Console operator obtains the generated credentials from the User Operator secret.

[source,shell]
----
cat k8s/console/console-scram.yaml | envsubst | oc -n kafka-ui apply -f -
----

If the SCRAM listener has a different name, update `spec.kafkaClusters[0].listener` in `k8s/console/console-scram.yaml` to that listener name before applying it.

=== Log in with Kafka credentials interactively

For evaluation, you can let each Console user enter their own Kafka credentials instead of configuring `credentials.kafkaUser`. The Kafka listener must still use `scram-sha-512`, and every user must have a corresponding `KafkaUser` and the Kafka ACLs required for their work. Apply `console.yaml`, which deliberately omits `credentials.kafkaUser`:

[source,shell]
----
envsubst < k8s/console/console.yaml | oc -n kafka-ui apply -f -
----

In the Console homepage, select the Kafka cluster and click *Login to cluster*. Enter the SCRAM username and password from that user's `KafkaUser` Secret. This removes the operator's need to read a shared KafkaUser Secret, so the Secret `Role` and `RoleBinding` described above are not needed for this configuration.

[WARNING]
====
The Console documentation deprecates interactive Kafka login because entered credentials are transmitted through and stored by the Console. Use it only for trusted evaluation environments. For production, use an application-scoped OIDC Kafka authentication flow instead.
====

== Authentication with Dex (optional)

By default the console runs without authentication. To add a login page with local email/password credentials, you can deploy https://dexidp.io/[Dex] as a lightweight OIDC provider with static passwords — no external SSO required.

=== Generate credentials

Generate a bcrypt hash for the desired password:

[source,shell]
----
htpasswd -BinC 10 admin <<< "admin123" | cut -d: -f2
----

Generate a random client secret:

[source,shell]
----
openssl rand -hex 16
----

Set the environment variables (in addition to `KAFKA_NAMESPACE` and `CLUSTER_DOMAIN` set earlier):

Fish shell:

[source,shell]
----
set -x DEX_CLIENT_SECRET (openssl rand -hex 16)
set -x DEX_PASSWORD_HASH (htpasswd -BinC 10 admin <<< "admin123" | cut -d: -f2)
----

Bash shell:

[source,shell]
----
export DEX_CLIENT_SECRET=$(openssl rand -hex 16)
export DEX_PASSWORD_HASH=$(htpasswd -BinC 10 admin <<< "admin123" | cut -d: -f2)
----

=== Deploy Dex

[source,shell]
----
cat k8s/console/dex.yaml | envsubst | oc apply -f -
----

Wait for the Dex pod to be ready:

[source,shell]
----
oc rollout status deployment/console-dex
----

=== Deploy the secured console

Instead of `console.yaml`, use the secured variant that includes the OIDC configuration:

[source,shell]
----
cat k8s/console/console-secured.yaml | envsubst | oc apply -f -
----

The console will now redirect to a Dex login page. Use the credentials configured in the static passwords (default: `admin@example.com` / `admin123`).

== Clean up

To delete the console, you can use the following command:

[source,shell]
----
oc delete consoles.console.streamshub.github.com kafka-ui
----

If you deployed Dex for authentication, also remove its resources:

[source,shell]
----
oc delete deployment/console-dex service/console-dex route/console-dex secret/console-dex-config secret/console-dex-secrets sa/console-dex -n kafka-ui
oc delete clusterrole/console-dex clusterrolebinding/console-dex
----
